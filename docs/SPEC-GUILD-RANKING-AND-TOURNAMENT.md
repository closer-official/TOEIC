# 仕様: ギルドランキング・マップ削除 と 大会（毎週・賞品・管理者設定）

相談内容を整理し、現状・選択肢・実装方針をまとめます。

---

## 1. ギルドランキングの算出方法 および マップ機能の削除

### 1.1 現状

| 種類 | 算出方法 | 表示場所 |
|------|----------|----------|
| **ギルドランキング（寄付XP）** | `guilds.total_donated_xp` の降順。50件。メンバー数は別途 `guild_members` から集計。 | ギルド画面タブ「ギルドランキング」 |
| **THE GRAND FLOOR ランキング** | マップ上の占領スコア。`スコア = 占領マス数 + 城数×10 + min(占領日数, 365)`。日次スナップショット `grand_floor_daily_ranking` あり。 | ギルド画面タブ「THE GRAND FLOOR」内＋専用API |

つまり**ランキングは2系統**あります。

- **A) 寄付XPランキング** … ギルドの「寄付XP合計」のみで順位。マップとは無関係。
- **B) Grand Floor ランキング** … マップ（領土拡大・占領・城）のプレイ結果で順位。

### 1.2 マップ機能（THE GRAND FLOOR）の削除可否

**削除可能です。**

- **フロント**: ギルド画面の「THE GRAND FLOOR」タブ、`/guild/grand-floor-map` ページ、該当リンクを削除。
- **API**: `/api/grand-floor/*`（state, map, check-in, expand, conquer, world, ranking）を削除または無効化。
- **DB**: `grand_floor_world`, `grand_floor_cells`, `grand_floor_mine_claims`, `grand_floor_daily_ranking` および `guilds` の `grand_floor_hq_x`, `grand_floor_hq_y`, `grand_floor_joined_at` は、削除する場合マイグレーションで削除可能（既存マイグレーションで CASCADE あり）。
- **ライブラリ**: `@/lib/grand-floor` はマップ専用のため、マップ削除なら不要になる。

**削除した場合のギルドランキング**

- **寄付XPランキング**はそのまま残せます（`/api/guild/ranking` とギルド画面の「ギルドランキング」タブのみで完結）。
- Grand Floor ランキングはマップと一体のため、マップ削除と同時に廃止になります。

**推奨**

- マップをやめるなら「**マップ＋Grand Floor ランキングを削除し、ギルドランキングは以下いずれか1本に**」する形でよいです。

### 1.3 ギルドランキングの代替案（寄付XP以外の「面白み」）

寄付XPだけだと単調になりがちなため、次のような案があります。

| 案 | 算出方法 | 面白み・特徴 |
|----|----------|--------------|
| **A) 寄付XP（現状）** | ギルドの `total_donated_xp` 降順 | シンプル。貢献の「量」だけ。 |
| **B) ギルド実力（合計ベストスコア）** | メンバー各自の「単語+Part5 ベスト合計」の**合計**で順位。 | 「ギルド全体の実力」がランキングに直結。強いメンバーを集めると上がる。 |
| **C) 週間活動スコア** | 直近7日間の「メンバーのプレイ回数・正解数・獲得XP」などをポイント化して合計。 | 週ごとに変動。「今週頑張ったギルド」がわかりやすい。 |
| **D) 寄付XP ＋ 活動ボーナス** | 基本は寄付XPだが、週間プレイ人数やプレイ回数に応じて加算。例: 寄付XP + (今週プレイした人数 × 100)。 | 寄付だけでなく「出てきてプレイしている人数」も反映。 |
| **E) 貢献の多様性** | 寄付XPは使うが、「寄付した人数」「プレイした人数」で補正や別枠表示。例: 「今週3人以上が寄付したギルド」をハイライト。 | 一人で溜めるより、みんなで少しずつ、が評価される。 |

**おすすめの組み合わせ**

- **B) ギルド実力** … ランキングの主軸にすると「強いギルド」がはっきりし、対戦意識が出やすい。既存の `runs_best_per_user` と `guild_members` で集計可能。
- あるいは **D) 寄付XP＋活動ボーナス** … 現行の寄付XPを活かしつつ、週の活動で差がつくようにする。

どれを主ランキングにするか決めていただければ、マップ削除後の「ギルドランキング」の算出をその方式に合わせます。

### 1.4 ギルド実力・週間集計・翌月曜報酬（確定仕様）

**採用**: **ギルド実力**を週ごとに集計し、**月〜日**の結果に応じてランキングを出し、**翌月曜**に上位へランキング報酬を付与する。

| 項目 | 内容 |
|------|------|
| **集計期間** | 月曜 0:00 JST 〜 日曜 23:59:59 JST（1週間） |
| **ギルド実力の定義** | その週にギルドメンバーが記録したスコアで集計。案: (A) メンバーごとの「その週のベスト（Part5+単語合計）」の合計、(B) その週の全 run のスコア合計。どちらも「週間」に紐づく集計が必要。 |
| **ランキング** | 上記スコアの降順。上位 N 件（例: 10 または 20）を「ランキング上位」とする。 |
| **報酬付与** | **翌月曜**に、ランキング上位ギルドに報酬を付与。報酬の中身（ゲーム内通貨・アイテム・称号など）は別途定義。 |
| **DB** | 週間ギルドスコアを保存するテーブル（例: `guild_weekly_scores`: `guild_id`, `week_start_date`, `score`, `member_count` など）。翌月曜のバッチ or 手動で「ランキング確定」と「報酬付与」を実行。 |

**実装の流れ**

1. 週の区間（月〜日）をキーに、メンバーの run を集計してギルドごとの「週間スコア」を算出。
2. 週間スコアでランキングを表示（ギルド画面・ランキング欄）。
3. 翌月曜に「前週のランキング」を確定し、上位に報酬を付与する処理（cron または管理者「報酬付与」ボタン）。

## 2. 大会の内容・優勝者の決め方・賞品・条件（確定仕様）

### 2.1 現状

- **大会ページ** (`/tournament`): 次回大会までのカウントダウンのみ。「参加する」ボタンは disabled。
- **開催**: 初回 2025-03-15、以降毎週日曜（コード上は固定）。
- **優勝者決定・賞品・条件・管理者設定**: 未実装。

### 2.2 大会の開催時間・参加方法・スコア（確定）

| 項目 | 内容 |
|------|------|
| **開催時間** | **日曜 12:00 JST 〜 23:00 JST** のみ。この時間帯以外は大会に参加・提出できない。 |
| **参加方法** | 日曜 12:00〜23:00 の間に、**Part5 に1回・単語に1回のみ**チャレンジ可能（計2本）。 |
| **大会スコア** | その **Part5 1本のスコア ＋ 単語 1本のスコア** の**合算**で勝負。週のベストではなく「その日の2本の合計」が大会スコア。 |
| **優勝者** | 合算スコアの1位。同点は先にそのスコアを記録したユーザーを1位とする等、ルールを1つ決める。 |

**実装の要点**

- 大会専用の「大会 run」を記録するテーブル or `runs` に `tournament_week_id` + `tournament_slot`（part5 / vocab）を付与し、**1ユーザー・1週あたり Part5 1本・Vocab 1本まで**に制限する。
- 受付時間はサーバー側で **日曜 12:00〜23:00 JST** のみ受け付ける（それ以外は 403 等で拒否）。
- 大会ページでは「参加する」で Part5 または 単語 の**大会用プレイ**を開始。各1回ずつまで。

### 2.3 優勝者と賞品の送付（確定）

| 項目 | 内容 |
|------|------|
| **認証** | 参加時点で **Apple ID またはメールアドレス** による認証が済んでいる前提。優勝者はそのアカウントに紐づくメールアドレスで特定できる。 |
| **賞品送付** | **運営が主導**で、優勝者のメールアドレスに賞品（アマゾンギフト等）を送る。アプリ側では「優勝者と連絡先（メール）」を管理者画面で確認できるようにし、送付は手動（運営がギフトコードを送る等）でよい。 |
| **管理者** | 優勝者確定後、管理者画面で「今週の優勝者」「連絡先メール」を表示。運営がそのメールに賞品を送付。 |

**DB**: 優勝者記録に `winner_user_id` と、表示用に `profiles` から取得したメール（または Apple のマスク済みメール）を保存・表示する。

### 2.4 大会の「条件」：運営がボタン・スライダーで設定（確定）

**要件**: 週ごとに**全員が同じ条件**でプレイする。条件は**運営が管理者画面でボタン・スライダーで設定し「決定」**するだけで反映される。

| 条件の種類 | 内容 | UI（案） |
|------------|------|----------|
| **計20種類の装備** | どの装備を「使用可」にするか、または装備を「すべてオフ」にするか。各装備をオン/オフするボタン、または「装備なし」「全装備可」のトグル。レベルを固定する場合はスライダーで「全員このレベル」など。 | 20種それぞれにチェックボックス or スライダー（レベル 0〜N）。「すべてオフ」1クリック。 |
| **個人の成長** | 進化（evolution）・個人レベル等のボーナスを「あり」か「なし」か、または固定値。 | トグル「個人成長あり/なし」またはスライダーでレベル固定。 |
| **ギルドの成長** | ギルドレベル等のボーナスを「あり」か「なし」か、または固定値。 | トグル「ギルド成長あり/なし」またはスライダーでレベル固定。 |

**ルール設定の ON / OFF**

- **ルール設定ボタン OFF**  
  - 装備・個人の成長・ギルドの成長の**制限なし**。参加者は**自分が育てている装備・成長をそのままフルに使用**できる（通常プレイと同じ）。
- **ルール設定ボタン ON**  
  - その週は「条件あり」になり、**20種の装備の使用可能トグルとそれぞれのレベル設定スライダー**が管理者画面に出現。  
  - 個人の成長・ギルドの成長も ON で設定可能。  
  - **「決定」**で保存すると、日曜 12:00〜23:00 の参加者は**全員この設定どおりの同じ条件**でプレイする。

**運用フロー**

1. 管理者画面で「今週の大会条件」を開く。
2. **ルール設定**を ON にする → 20装備（使用可チェック＋レベルスライダー）・個人の成長・ギルドの成長が表示され編集可能。OFF のままなら「全員フル使用」。
3. **「決定」**を押すと、その週の大会ルールとして保存される。
4. 日曜 12:00〜23:00 にユーザーが大会に参加すると、**ルール ON なら全員同じ条件、OFF なら各自フル使用**。クライアントは「今週の大会ルール」を API で取得し、`rulesEnabled: false` なら通常ロードアウト、`true` なら `rules` に従ってスコア計算。

**技術メモ**

- `tournament_weeks` に **`rules`** (JSON) を保存。例: `{ "equipment": { "allowed_ids": [] | ["id1","id2",...], "level_fixed": 0 }, "personal_growth": false, "guild_growth": false }` など。装備20種の ID は `equipment-items` と一致させる。
- ゲーム開始時（大会モード）: API で `GET /api/tournament/current-rules` を叩き、取得した `rules` に基づいて装備効果・evolution・ギルドボーナスを適用 or 無効化する。
- 管理者画面: フォームで各項目を編集 → 「決定」で `PUT /api/admin/tournament-rules` に送信。

### 2.5 賞品の管理（管理者で変更可能）

- **保存するもの**  
  - 週の識別（`tournament_weeks.start_date` など）  
  - 賞品の説明文（例: 「アマゾンギフト券 3000円分」）  
  - 金額（円、任意・表示用）  
  - **条件** `rules` (JSON)：装備20種・個人の成長・ギルドの成長の設定

- **管理者画面**  
  - 「今週の大会」に対して **賞品**（説明・金額）と **条件**（2.4 のボタン・スライダー）を編集。  
  - 条件は「決定」で保存。賞品も同じフォーム or 別タブで保存。  
  - 優勝者確定後は「今週の優勝者」「連絡先メール」を表示（賞品送付用）。

- **大会ページ**  
  - 次回開催は**日曜 12:00〜23:00** と表示。  
  - 「今週の賞品」「今週の条件」（装備・個人・ギルドの要約）を API から表示。  
  - 参加中は「Part5 1回 / 単語 1回」の残り回数と、合算スコアを表示。

### 2.6 実装タスク一覧（確定に沿った案）

1. **DB**
   - **大会週** `tournament_weeks`: `id`, `start_date`（その週の日曜）, `prize_label`, `prize_yen`, **`rules`** (JSON: 装備・個人・ギルド), `winner_user_id`, `winner_email_display`（表示用）など。
   - **大会 run** 用: `runs` に `tournament_week_id` + `tournament_slot` ('part5' | 'vocab') を追加し、1ユーザー・1週で part5 1本・vocab 1本までに制限。または大会専用テーブル `tournament_runs`。
   - 提出時刻は日曜 12:00〜23:00 JST のみ許可（サーバー側で検証）。

2. **API**
   - **公開**: `GET /api/tournament/current` … 今週の賞品・条件（`rules`）・開催時間。  
   - **公開**: `GET /api/tournament/current-rules` … ゲーム開始時にクライアントが参照する `rules` のみ。  
   - **参加者**: 大会 run の提出（日曜 12:00〜23:00、Part5/Vocab 各1回まで）。  
   - **管理者**: 賞品・条件（`rules`）の更新、優勝者確定、優勝者・メール表示。

3. **管理者画面**
   - **大会設定**: 今週の賞品（説明・金額）＋条件（装備20種のオン/オフ・個人の成長・ギルドの成長をボタン・スライダーで設定）→「決定」で保存。  
   - **優勝者**: 「今週の優勝者を確定」ボタン、確定後の「優勝者名」「連絡先メール」表示。

4. **大会ページ**
   - 日曜 12:00〜23:00 のカウントダウン or 参加可能である旨の表示。  
   - 賞品・条件の要約。「参加する」→ Part5 または 単語 の大会用プレイ（各1回）。合算スコア表示。

5. **ゲーム側（大会モード）**
   - 大会用プレイ開始時に `current-rules` を取得し、`rules` に従って装備効果・個人成長・ギルド成長を適用 or 無効化してスコア計算。  
   - 提出時は `tournament_week_id` + `tournament_slot` を付与し、時刻チェック（12:00〜23:00）・回数制限（各1回）をサーバーで検証。

## 3. 次のステップ

1. **ギルド・マップ**  
   - マップ削除で進めるかどうか確定。  
   - ギルドランキングは **1.4 ギルド実力・週間集計・翌月曜報酬** の仕様で実装。

2. **大会**  
   - 上記 **2.2〜2.6**（日曜 12:00〜23:00、Part5・単語各1回、合算スコア、賞品は運営が優勝者メールに送付、条件はボタン・スライダーで設定）の順で DB → API → 管理者画面 → 大会ページ → ゲーム（大会モード）を実装。

このドキュメントの確定仕様に沿って、削除手順（マップ）とテーブル・API・UI の具体的な差分まで落として実装に進めます。
