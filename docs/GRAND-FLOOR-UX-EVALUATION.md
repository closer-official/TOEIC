# THE GRAND FLOOR 仕様・UX 評価（ゲームデザイン観点）

ゲームクリエイター・デザイナー視点での評価。使いにくさ・わかりにくさ・改善案を列挙する。

---

## 1. マップ操作が感覚的でない（最優先級）

### 1.1 ジェスチャーが使えない
- **現状**: パン・ズームは「←→↑↓」と「＋／－」ボタンのみ。
- **問題**: スマホでは「ドラッグで移動」「ピンチで拡大縮小」が当たり前。ボタンだけでは直感的でなく、特に片手操作でやりづらい。
- **改善**: マップ領域での **ドラッグでパン**、**ピンチ（またはダブルタップ）でズーム** を実装する。ボタンは補助として残す。

### 1.2 パンが離散的
- **現状**: 1回の操作で 5 マスずつしか動かない。
- **問題**: 「ちょっと右に見たい」が伝わりにくく、細かい位置合わせがしづらい。
- **改善**: ドラッグ時は **連続的なスクロール（またはビューポートの連続移動）**、ボタンは「だいたい 1 画面分」などの大きな移動用にする。

### 1.3 ズームの意味が直感的でない
- **現状**: 「＋」で表示範囲が狭く（拡大）、「－」で広く（縮小）。座標の span で制御。
- **問題**: ボタンラベルが「＋／－」だけだと、地図アプリの「＋＝拡大」と一致するが、**何マス見ているか** がユーザーに伝わっていない。またズーム中に毎回 API 再取得しており、体感が重い。
- **改善**: ラベルを「拡大」「縮小」にする、またはアイコン（虫眼鏡＋／－）にする。可能ならクライアント側でタイル/画像を拡大縮小し、必要時だけ再取得する方式を検討。

### 1.4 マップが「触れない」
- **現状**: マスは `<div>` で描画されているが、クリック・タップで何も起きない（`title` のみ）。
- **問題**: 見るだけの画面に感じられ、「ここを拡大したい」「ここを占領したい」という欲求に応えられない。
- **改善**: 後述の「マス選択→拡大/占領」とあわせ、**タップで選択・アクション** を可能にする。

## 2. 占領・拡大がマップからできない（最優先級）

### 2.1 アクションの入口がない
- **現状**: 拡大は POST `/api/grand-floor/expand`、占領は POST `/api/grand-floor/conquer` で可能だが、**UI から呼ぶ手段がない**。ギルドタブには「リーダー・幹部のみ」と書いてあるだけ。
- **問題**: プレイヤーから見ると「占領ができない」「拡大のやり方がわからない」と感じる。ルールはあるがプレイできない。
- **改善**: マップ画面で **マスをタップ → そのマスが「拡大可能／占領可能」ならメニューまたはモーダルを表示 → コスト確認 → 実行** の流れを実装する。

### 2.2 どこに拡大・占領できるかわからない
- **現状**: 「自陣に隣接するマスに拡大」「敵マスに占領」と仕様ではなっていても、画面上で **どのマスが対象か** の強調や説明がない。
- **問題**: ルールを読まないと何もできず、読んでもマップと対応づけにくい。
- **改善**: マス選択時や、モード切替（「拡大可能マス表示」「占領可能マス表示」）で、**拡大可能マス・占領可能マスをハイライトや枠で示す**。ツールチップや吹き出しで「隣接しているため拡大可能」等の一文を出す。

### 2.3 コストが事前に見えない
- **現状**: 拡大 5000×2^(n-1) XP、占領は敵の累計 XP の 2 倍（城は 3 倍）と仕様にあるが、**選択したマスに対する必要 XP が画面に出ない**。
- **問題**: 「やってみたら XP が足りなかった」となりやすく、不信感や離脱につながる。
- **改善**: マス選択時または拡大/占領モーダルで **必要 Guild XP** と **現在のギルド XP** を併記する。足りない場合は「あと ○○○ XP 必要」と表示する。

### 2.4 権限が画面と一致していない
- **現状**: リーダー・幹部のみ拡大・占領可能だが、マップ画面では **自分が幹部かどうか** や **実行ボタンの有無** がはっきりしない。
- **問題**: 一般メンバーがマップを開いても「何をしていいかわからない」、幹部が「自分にできる」と気づきにくい。
- **改善**: マップ上部や state 取得結果で「拡大・占領はリーダー/幹部のみ」とロールを表示する。**実行権限がない場合は「この操作はリーダー・幹部のみ」とメッセージを出し、拡大/占領ボタンは出さないかグレーアウト** する。

## 3. チェックイン（本拠地選択）のわかりにくさ

### 3.1 候補地がマップ上でわからない
- **現状**: 3 候補が「(x, y) — 要塞型/資源型/フロンティア型」のテキストリストだけ。
- **問題**: どこが山に近いか、どこが端か、どの資源に近いかが **マップと対応づけできない**。戦略的な選択がしづらい。
- **改善**: 候補表示時に **簡易マップまたはサムネイル** で 3 箇所の位置を表示する。または「マップを開く」でマップを表示した状態で、候補座標に **ピンやハイライト** を出す（チェックイン前でもマップは見られるようにする）。

### 3.2 型の違いの効果が書いていない
- **現状**: 「要塞型」「資源型」「フロンティア型」という名前だけ。
- **問題**: それぞれ **何が有利で何が不利か**（防衛しやすい、資源に近い、敵が少ないなど）が説明されていない。初見では選びようがない。
- **改善**: 各候補の横に 1 行説明を追加する（例：「山に近く防衛に有利」「資源マスに近い」「マップ端で敵が少ない」）。

### 3.3 「固定・変更不可」の重みが伝わりにくい
- **現状**: 「3箇所から1つを選んで本拠地を設置してください（固定・変更不可）」とある。
- **問題**: 一度決めたら **絶対に変えられない** ことの重大さが、短い文言だけでは伝わりにくい。後から「失敗した」と思いやすい。
- **改善**: 選択前に「本拠地は一度決めると変更できません。慎重に選んでください」など、注意文を少し強調する。可能なら確認ダイアログで「この位置でよろしいですか？」と一度聞く。

## 4. 情報・フィードバックの不足

### 4.1 ギルド XP がどこにあるか不明
- **現状**: 拡大・占領は「Guild XP」を消費するが、**現在のギルド XP がマップ画面やギルドタブに表示されていない**（仕様上は `guilds.total_donated_xp` 等）。
- **問題**: 「いくら使えるか」がわからず、拡大・占領を試しにくい。
- **改善**: ギルドタブおよびマップ画面に **現在の Guild XP** を表示する。拡大/占領モーダルでは「消費後 ○○○ XP 残り」も出せるとなお良い。

### 4.2 スコアの意味が説明されていない
- **現状**: ランキングに「○ pt」とスコアだけ表示。
- **問題**: スコアが **占領マス数・城数・占領日数** の式で決まることが画面から読み取れない。何をすれば順位が上がるかわかりにくい。
- **改善**: ランキングの近くに「スコア = 領土マス数 + 城×10 + 占領日数（最大365）」のような **一言説明** を入れる。または「？」アイコンでツールチップ表示。

### 4.3 資源マスの効果が未実装なのに色だけある
- **現状**: 黄/紫/青で「未占領の資源マス」と凡例にあるが、**チップ鉱山・デルポイ・ヘルメスの効果は未実装**。
- **問題**: 色分けだけされていて「占拠すると何が起こるか」がプレイでは何も起こらない。期待と実態のギャップが大きい。
- **改善**: 凡例やヘルプで「資源マス（効果は準備中）」などと明記する。実装後は「占拠でチップ取得」「占拠で敵情報表示」等の短い説明を入れる。

### 4.4 重ねがけ・城・サプライラインの説明がどこにもない
- **現状**: 同一マスへの重ねがけで Level 5 が城、本拠地＋城から繋がっていない領土は中立化、と仕様にあるが、**ゲーム内のヘルプやチュートリアルがない**。
- **問題**: ルールを理解しないままプレイすると、占領したつもりがサプライライン切断で領土を失ったときなどに混乱する。
- **改善**: 「THE GRAND FLOOR のルール」または「？」ヘルプで、**拡大・占領・城・サプライライン** を 3〜5 行ずつ説明する。初回のみショートチュートリアルを出すのも有効。

## 5. 画面構成・導線

### 5.1 マップとギルドタブの役割が分かれすぎている
- **現状**: ギルドタブで「本拠地・領土数・城数」と「マップを開く」「ランキング」を見る。マップページでは見る＋操作ボタンのみで、**拡大・占領の実行はどちらの画面からもできない**。
- **問題**: 「マップで戦略を考えて、その場で拡大・占領したい」という自然な流れができない。画面が「見る用」と「説明用」に分かれており、行動に結びつきにくい。
- **改善**: **マップを「見る＋拡大・占領する」の一つの場所** にし、ギルドタブは参加状況・ランキング・Guild XP 表示に特化する。

### 5.2 凡例が小さく読みにくい
- **現状**: マップ下に 10px 程度のテキストで凡例が 1 行。
- **問題**: スマホではとくに読みづらく、色の対応を何度も見返すことになる。
- **改善**: 凡例を **アイコン＋短いラベル** の行分け、または折りたたみの「凡例」セクションにして、必要時だけ展開できるようにする。

### 5.3 座標表示が一般プレイヤーに不要
- **現状**: 「範囲: (0,0) ～ (25,25)」のように数値が表示される。
- **問題**: 上級者には有用だが、多くのプレイヤーには **どの方向にどれくらい見ているか** の感覚の方が重要。数値だけだととっつきにくい。
- **改善**: オプションで非表示にできるようにするか、 secondary な情報として小さくする。「北側を表示中」のような文言を足すだけでもよい。

## 6. その他の使いにくさ・わかりにくさ

### 6.1 ローディング時の体験
- **現状**: パン・ズームのたびに API で再取得し、その間は前のマップを表示したままか、ローディング表示になる。
- **問題**: 操作のたびに **待ち時間** を感じやすく、スムーズな「探検」感が出しにくい。
- **改善**: 可能なら前回結果を残したまま裏で取得し、取得完了時にスムーズに差し替える。または「読み込み中」をマップ上に小さく表示して、画面全体を隠さない。

### 6.2 エラー時の案内が弱い
- **現状**: エラー時は `setError` で短文を表示する想定。
- **問題**: 「マップの取得に失敗しました」だけだと、**なぜ失敗したか・何をすればよいか** が伝わりにくい（ネット不良、権限、メンテ等）。
- **改善**: エラー種別に応じて「通信環境を確認してください」「しばらく経ってから再試行してください」などの案内を追加する。

### 6.3 ランキングの日付切り替えが UI にない
- **現状**: API は `?date=YYYY-MM-DD` で過去日のスナップショットを返せるが、**日付を選ぶ UI がない**。
- **問題**: 過去の順位の推移をプレイヤーが自分で確認できない。
- **改善**: 日次スナップショット登録が実装されたら、ランキング表示で **日付セレクト** を追加する。

### 6.4 他ギルドの色が区別しづらい
- **現状**: 他ギルドは `guild_id` のハッシュで HSL 色を割り当て。似た色になることがある。
- **問題**: 複数ギルドが隣接していると、**どれがどのギルドか** が色だけでは判別しづらい。
- **改善**: マスにホバー/タップしたときに **ギルド名を表示** する。凡例に「他ギルドはタップで名前表示」と書く。

## 7. まとめ：優先して直したいこと

| 優先度 | 内容 |
|--------|------|
| 高 | マップの **ドラッグでパン・ピンチでズーム** の実装 |
| 高 | マップ上で **マスをタップ → 拡大/占領の実行** とコスト・確認表示 |
| 高 | **拡大可能マス・占領可能マス** のハイライトまたは明示 |
| 高 | **現在の Guild XP** の表示（ギルドタブ・マップ） |
| 中 | チェックイン候補を **マップ上で位置表示**（ピン等） |
| 中 | **ルール・スコア式の短い説明**（ヘルプまたは初回説明） |
| 中 | 資源マスの **効果の説明** または「準備中」の明記 |
| 低 | ランキングのスコア式の説明、凡例の見やすさ、日付選択 UI |

上記を踏まえて、まずは「マップ操作の直感性」と「マップから拡大・占領できるようにする」の 2 本柱を実装すると、体感の使いやすさが大きく変わる。

## 8. ユーザー体験に基づく使いにくい個所（個数制限なく）

実際の操作・読み込み・画面から感じる「つかいにくさ」を、ユーザー体験ベースで列挙する。

### 読み込み・待ち時間

1. **初回マップ表示まで二重に待たされる**  
   マップページを開くと「state 取得」でローディング → その後「map 取得」でまたローディング。到着までに 2 段階で待ち時間を感じる。

2. **パン・ズームのたびに API 再取得で止まる**  
   ドラッグで移動したりピンチでズームしたりするたびに `/api/grand-floor/map` が走り、その間スピナーや半透明オーバーレイで「読み込み中」になる。操作のたびに止まるので、地図を滑らかに探している感覚にならない。

3. **読み込み中でも前のマップが残るが、操作はブロックされない**  
   再取得中は前フレームを表示したままなのはよいが、「今どこを向いているか」が確定するまでドラッグやズームを続けられ、結果として「今の表示と次の表示がずれる」体験になりやすい。

4. **拡大・占領実行後に必ず loadMap が走る**  
   1 マス拡大/占領しただけでもマップ全体を再取得するため、アクション後の待ち時間が長く感じる。

5. **ビューポート範囲が広いと API が重くなりやすい**  
   span が大きいと minX〜maxX, minY〜maxY の範囲が広がり、cells など取得量が増えて応答が遅くなりやすい。ユーザーには「ズームアウトすると遅い」と感じられる。

### 「今自分がどこにいるか」のわかりにくさ

6. **現在のビューポート中心の座標が画面に出ていない**  
   どの (x, y) を中心に見ているかが数値で表示されない。地図アプリのように「今ここを見ている」が一目でわからない。

7. **本拠地が画面のどこにあるか即座にわからない**  
   「本拠地」ボタンを押すと中心が HQ に飛ぶが、HQ が今の画面内にあるか・どの方向にあるかは、ボタンを押すまで分からない。常に「HQ は今の画面の左上付近」のように相対位置が出ているとよい。

8. **マップ全体に対する自分の位置感覚がない**  
   ワールドが 100×100 などと仕様では決まっていても、画面上に「全体の何割を見ているか」「上下左右にまだどれくらいあるか」が伝わらない。ミニマップや簡易な「ワールド内での位置」表示があるとよい。

9. **ズームレベル（何マス幅で見ているか）が数字で出ていない**  
   span で 25 や 15 など変わるが、UI には「約 25 マス幅で表示中」のような説明がない。拡大しすぎ・縮小しすぎの判断がしづらい。

10. **ドラッグ後に「どのマスを中心にしたか」がフィードバックされない**  
    ドラッグで中心が変わっても、新しい中心座標や「本拠地から北に○マス」のような情報が表示されない。

### 操作・導線

11. **＋／－ボタンが「拡大」「縮小」ではなく記号だけ**  
    「＋」「－」だけだと、地図の「拡大・縮小」と結びつきにくい人や、どちらが広がりでどちらが狭がりか一瞬迷う。ラベルやアイコンで「拡大」「縮小」と明示した方がよい。

12. **方向ボタン（←→↑↓）が 5 マス固定で細かく合わせづらい**  
    「ちょっとだけ右」ができず、5 マス単位でしか動かない。ドラッグはあるが、ボタンだけ使うユーザーには細かい位置合わせがしづらい。

13. **「本拠地」ボタンが小さい・目立たない**  
    自分がどこにいるか分からなくなったときに頼りになる「本拠地へ」が、他ボタンと同様のスタイルで並んでいると、初見で気づきにくい。

14. **タップとドラッグの判定が「8px 未満ならタップ」に依存している**  
    指が少し動いただけでドラッグ扱いになり、マスをタップしたつもりが反応しない、または逆にタップのつもりがパンになってしまうことがある。閾値や「タップ用／パン用」の切り替えがあるとよい。

15. **メンバーは拡大・占領できないが、その説明がマップ上で弱い**  
    「（拡大・占領はリーダー/幹部のみ）」と小さく出ているだけなので、メンバーが「なぜタップしても何も起きないか」をその場で理解しづらい。

### 情報・フィードバック

16. **領土数・城数がマップ画面に出ていない**  
    ギルドタブにはあるが、マップページには「領土 ○ マス・城 ○」のようなサマリがない。マップを見ながら現状を確認しづらい。

17. **拡大・占領可能マスが緑・赤枠だが、色覚や画面によって判別しづらい**  
    枠線だけだと見逃したり、他色と紛れたりしやすい。アイコンや「拡大可」「占領可」の短いラベルがあるとよい。

18. **実行後「拡大しました」「占領しました」が 3 秒で消えるだけ**  
    どのマスが変わったか、領土数がどう増えたかなど、次のアクションに繋がる情報がすぐには残らない。

19. **エラー時に「なぜ失敗したか」が不足しがち**  
    API が 400/403/500 を返しても、クライアントでは短文のメッセージだけのことが多く、権限不足・XP 不足・1日1回制限など原因別の案内が弱い。

20. **凡例が 1 行・小さいフォントで読みにくい**  
    スマホで「黄＝自領」「緑枠＝拡大可能」などを何度も見返す必要があり、特に初回は負荷が大きい。

### 画面構成・導線

21. **マップを開く入口が「マップを開く →」リンクだけ**  
    ギルドタブの THE GRAND FLOOR セクション内にしかなく、他画面から「Grand Floor マップだけ」に直接行く導線が少ない。

22. **チェックイン前はマップを見られない**  
    本拠地未設定の状態では「参加していません」となり、候補選びの前にマップで全体像を把握できない。

23. **ランキングとマップが別画面で、行き来が何度も発生する**  
    マップで戦略を考えたあとランキングを確認する、という流れでタブやページを切り替える回数が増える。

24. **ルール・スコア式がマップ画面にない**  
    ギルドタブの折りたたみにはあるが、マップで「どういうルールで動いているか」を参照しづらい。

### その他

25. **資源マス（黄/紫/青）の効果が「準備中」で、占拠メリットが伝わらない**  
    色と凡例だけでは「なぜこのマスを狙うか」が分からず、戦略が立てにくい。

26. **他ギルド領が guild_id ハッシュ色で、名前はツールチップのみ**  
    複数ギルドが隣接していると、色だけでは誰の領土か判別しづらく、タップしないと名前が出ない。

27. **城（Lv.5）と通常領土の見た目差が「明るい黄／暗い黄」程度**  
    城の重要さが視覚的に強く出ておらず、どこが要所か把握しづらい。

28. **モバイルでマップ領域が「min(70vh, 480px)」固定**  
    機種や向きによっては、もっと大きくマップを見たい・操作したいという要望に応えられていない。

29. **ピンチズーム時に API が都度呼ばれ、指を離すたびに再取得**  
    ピンチの最中は span が変わるたびに loadMap が走る可能性があり、通信と描画が重くなりやすい。

30. **初回 state 取得中はマップ用の ResizeObserver がまだ効いていない**  
    state 未取得だとマップ領域が描画されず、コンテナサイズの計測が遅れ、初回表示のレイアウトが一瞬不安定に見えることがある。

---

上記は「読み込みが遅い」「今どこにいるかわかりにくい」を中心に、ユーザーが実際にぶつかりやすい使いにくさを列挙したもの。改善時は **読み込みの軽減・非ブロック化** と **現在位置・ビューポート・本拠地の明示** を優先すると、体感が大きく変わる。
