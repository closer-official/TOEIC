# マイグレーション 1本化について

「どのSQLをやったかわからなくなった」場合、**既存のマイグレーションをすべて削除し、1本のフルスキーマにまとめる**のは問題ありません。

## 条件

- **開発環境**で、**DBをリセットしてよい**場合に有効です。
- **本番で既にマイグレーションが適用されている**場合は、ファイルを消すと履歴と不整合になるため、やらないでください。

## 手順

1. **バックアップ**（本番データがある場合は必ず取得）
2. **既存のマイグレーションを削除**  
   `supabase/migrations/` のうち、`00000000000001_full_schema.sql` とこの README 以外の `.sql` を削除する。
3. **DBをリセットして適用**  
   ローカルなら:
   ```bash
   supabase db reset
   ```
   これで `00000000000001_full_schema.sql` だけが適用され、現在のスキーマが一から作られます。
4. リモート（Supabase クラウド）でやり直す場合は、ダッシュボードで「Database reset」するか、プロジェクトを作り直したうえで `supabase db push` でこの1本を適用してください。

## ファイル構成（1本化後）

- `00000000000001_full_schema.sql` … 現在の全テーブル・RLS・ポリシー・ストレージ・関数をまとめた1本
- `README_CONSOLIDATION.md` … この説明

`000_full_schema_copy_paste.sql` は「SQL Editor にコピペ用」の参考だったため、マイグレーションとしては残していません。必要なら 00000000000001 の内容をコピーして使ってください。
